a #247 — the deployment profile as a table, 80×26


  
Four profiles (Orbit's standard, processing, ai, full), one row each,
    three columns: the name, what the profile adds, and whether it can be installed today. The block is centred as a unit;
    columns share a left edge. The caret rides two cells left of the name, as on every menu. Rows that cannot be installed
    are faint, and say so in their own row — the "only Standard is available so far" line below the menu goes. A memory column
    waits for figures Orbit's documentation does not yet give.


  
b #247 — the same at 50 columns

  

  
Under 68 columns the table has no room for its middle column, so each profile takes two rows: name and
    availability, then what it adds beneath, indented to the name. Same words, same colours, nothing cut.






  
c #249 — the notice shows there is more, and how to get there, 80×26

  

  
Two additions, this screen only. A scroll track in the prose block's right gutter: a faint │ per prose row,
    with a ┃ thumb in the muted ink whose length and position are the viewport's share of the whole notice. A hint row, the
    last row of the viewport, in the muted ink: more below · press ↓ or scroll the mouse wheel. Both name only inputs that work here.
    The last visible prose row still steps down to faint, as today.


  
d #249 — the end has been seen

  

  
Once the whole notice has been on screen the hint row goes blank, the way the countdown does when its gate is passed;
    the track stays, thumb at the bottom, so the person still sees where they are.






  
e #254 — the splash says what is wrong, 80×26

  

  
The status word keeps its place and colour; the reason joins it on the same row after the house separator:
    degraded · not responding. One more row beneath, in the muted ink, when the launcher can ask Docker: 2 of 3 services running.
    Repair is already preselected on a degraded deployment; the caret is the pointer, so no sentence says "go to Repair".


  
f #254 — the launcher could not tell

  

  
The reason is one of five words the probe can actually tell apart: not responding (refused or timed out),
    address not found (no DNS answer), server error (a 5xx reply), certificate rejected (TLS), and
    could not check for anything else. The services row appears only when Docker answered; a count is never guessed.






  
g #255 — Repair opens with the services and their states, 80×26

  

  
A services block above the findings: every service the deployment's profile expects, one row each, in Compose order.
    Three glyphs, three colours: ✓ running (green), ! faulted (amber: starting, restarting, stopped, unhealthy — the
    state word says which), ✗ missing (red: no container exists). Names are the container names, because that is what
    docker ps shows. The list is read-only.


  
h #255 — a short terminal, 80×20

  

  
When the full list and the plan will not both fit, the running services collapse to one row — ✓ 3 running — and
    every faulted or missing service keeps its row. What is wrong is never the part that gets hidden.









  
The calls

  
#247 table

  
Columns: name · what it adds · availability. Block centred as a unit, columns aligned — a deliberate exception to "menu items
     centre individually", because the owner asked to compare the options. Unavailable rows faint, each saying not yet.
     Narrow terminals stack each row in two. Memory column deferred until Orbit publishes figures.

  
#249 scrolling

  
Track in the right gutter + one hint row at the viewport's foot. The hint is the one key hint in the app, allowed here by
     the owner's own instruction (2026-10-17); it names ↓ and the mouse wheel only, both of which scroll this screen. Blank
     once the end has been seen.

  
#254 reasons

  
degraded · reason on the status row, reason from one of five words the probe can tell apart. A services count row
     only when Docker answered. "Could not check" when the launcher does not know.

  
#255 services

  
Expected set = app, db, clamav always; tika for processing and full; ollama for ai
     and full (from COMPOSE_PROFILES in .env-orbit). State from docker compose ps -a
     for the folder's project. Running rows collapse first when the screen is short.
